# Советы по geai

Отдельно от описания устройства (`HOW_GEAI_WORKS.md`): практические рекомендации — как
сделать работу дешевле, быстрее и точнее, и куда развивать плагин.

---

## A. Стоимость и эффективность

1. **Подписка вместо поштучного API.** Включи Claude Code engine (`useClaudeCodeEngine`) —
   ход идёт через CLI по твоей подписке, без оплаты токенов по API. Лучший вариант для
   ежедневной работы.
2. **Prompt caching (Anthropic).** Уже встроен: `cache_control: ephemeral` на system-блоке и
   последнем инструменте (`AnthropicClient.kt`). Повторяемый префикс (доктрина + каталог
   тулзов) превращается в дешёвые cache-hits. Эффект тем выше, чем длиннее сессия.
3. **Модель под задачу.** Навигация/мелкие правки — `claude-haiku-4-5` (≈90% качества, кратно
   дешевле). Сложный root-cause / архитектура — `claude-opus-4-8`. Повседневно —
   `claude-sonnet-4-6`. Меняется в Settings → Tools → Geai.
4. **`kb_lookup` перед поиском.** Индекс знаний отдаёт `file:line` без сканирования и без
   раздувания контекста. Один `kb_record` для горячих символов окупается во всех следующих
   ходах.
5. **Тюнинг бюджетов.** `maxContextTokens` выставь равным реальному окну модели (200k для
   Claude, меньше для локальных). `maxTokens` (ответ) держи умеренным — раздутый резерв зря
   ужимает входной контекст в компрессоре.
6. **Узкое чтение.** Доктрина уже требует читать диапазонами строк — это прямо снижает расход
   токенов на крупных файлах.

---

## B. Качество диагностики

1. **Пиши LESSON-записи.** Грабли, на которые агент наступил, фиксируй через `kb_record`
   (ось LESSON) — он трактует их как жёсткие ограничения и не повторит.
2. **Держи доктрину короткой.** Любой текст в `SystemPrompt.BASE` уходит в КАЖДЫЙ запрос.
   Добавляя правила, удаляй устаревшие — длинная доктрина дорожает линейно.
3. **Снимок проекта — дёшево, но поверхностно.** Для монорепо/множества модулей стоит
   расширить `ProjectContextGatherer` (например, отметить активный модуль), но осторожно с
   объёмом.

---

## C. Автономность и безопасность

1. **`autoApproveEditTools` — осознанно.** `true` = полная автономия (правки/команды без
   вопросов) — удобно в доверенном проекте/песочнице; `false` = апрув каждого мутирующего
   действия — для чужого/боевого кода. Это и есть рубильник «дёшево-автономно vs безопасно».
2. **Конечным пользователям возни с `.claude/` не нужно.** Файл прав `.claude/settings.json`
   относится только к разработке *исходников* geai через Claude Code. Поставивший `.zip`
   пользователь его не касается (см. ниже §E).
3. **Конфайнмент уже включён.** `run_command`/`write_file` ограничены корнем проекта, MCP
   закрыт токеном — не отключай эти проверки ради удобства.

## D. Куда развивать (roadmap)

Приоритет по «эффект / усилие»:

1. **PSI-навигация** — `find_usages`, `go_to_definition`, `list_symbols`, `rename_symbol`.
   Сейчас агент только grep'ает текст; ходьба по графу символов — качественный скачок для
   кодонавигации. Самый высокий приоритет.
2. **Стриминг ответов** — SSE у Anthropic/OpenAI; живой вывод вместо ожидания всего хода.
3. **Суммаризация в компрессоре** — сейчас старый контекст усекается; отдельный
   summarization-проход сохранит больше сигнала на очень длинных сессиях.
4. **Тесты на чистую логику** — `ContextCompressor`, `FsPaths`/конфайнмент, CAS в
   `GeaiKnowledgeStore`, маппинг LLM-клиентов. Сейчас покрытие ≈0%.
5. **detekt/ktlint** — статанализ в сборку. Нужен baseline на первом прогоне (иначе завалит
   билд замечаниями по легаси).

---

## E. Turnkey для контрибьюторов vs пользователей

- **Пользователь плагина:** установить `.zip` → вписать API-ключ (или включить Claude Code
  engine) → по желанию `autoApproveEditTools`. Больше ничего.
- **Контрибьютор (правит исходники через Claude Code):** закоммиченный
  `.claude/settings.json` с allow-листом `gradlew` даёт сборку без подтверждений в любом
  клоне. Сборка требует **JDK 21** (Kotlin 2.1.0 падает на JDK 25+), демон пиннится через
  `gradle/gradle-daemon-jvm.properties`. Для честной верификации правок —
  `./gradlew compileKotlin --rerun-tasks` (config cache иначе помечает задачу UP-TO-DATE и
  даёт ложно-зелёный билд).

# geai Roadmap — путь к лучшему кодинг-агенту

*Составлен на базе v0.0.70 (контекст-редизайн + Debugger 2.0 + UI). Язык — русский: рабочий документ.*

## Северная звезда

**geai — единственный агент, который доказывает диагнозы и фиксы наблюдением реального рантайма,
а не правдоподобным текстом.**

Все сильные конкуренты — текстовые: Claude Code, Cursor, Copilot Workspace, Devin, Junie читают
файлы и *предполагают*, что происходит при исполнении. geai живёт внутри IDE и имеет то, чего нет
ни у кого из них одновременно:

| Возможность | geai | Claude Code / Cursor / Devin |
|---|---|---|
| Семантический индекс (PSI: usages, implementations, diagnostics без сборки) | ✅ live | ❌ grep/LSP-частично |
| Управление дебаггером (breakpoints, step, evaluate) | ✅ | ❌ |
| Трейсинг значений в рантайме без остановки (tracepoints) | ✅ 0.0.69 | ❌ |
| Стоп на исключении с живым состоянием | ✅ 0.0.69 | ❌ |
| Провайдер-независимость (Claude/OpenAI/DeepSeek/Qwen/локальные) | ✅ | частично |

Каждое решение роадмапа проверяется вопросом: **усиливает ли это рантайм-моат или скорость/доверие
вокруг него?** Если нет — не делаем.

---

## Столп 1 — Рантайм-превосходство (моат)

Цель: замкнуть цикл «воспроизвёл → наблюдал → исправил → доказал» полностью внутри агента.

1. **Глаза на вывод программы** — `read_run_output`: захват stdout/stderr активных Run/Debug
   конфигураций через `ExecutionListener`/`ProcessListener` (кольцевой буфер на процесс) + `logcat`
   для Android (фильтр по пакету/tag/level). Сейчас агент слеп к тому, что печатает приложение, —
   это самая частая улика. **(S, максимальный эффект)**
2. **Вскрытие падения (failure autopsy)** — при паузе на исключении автоматически собрать
   структурированный отчёт: цепочка exception → стек → локалы по 3–5 верхним кадрам → строки кода.
   Один тул-вызов вместо десяти. **(S)**
3. **Runtime-diff как доказательство фикса** — прогнать сценарий с трейспоинтами ДО и ПОСЛЕ правки,
   показать разницу значений: «было `total=NaN` → стало `total=1240.50`». Фикс считается доказанным
   только с таким дифом. **(M, киллер-фича демо)**
4. **Watchpoints** — брейкпоинт на изменение поля («кто мутирует `state`?») через
   JavaFieldBreakpointType. Закрывает целый класс багов, недоступный текстовым агентам. **(M)**
5. **Замкнутый цикл с тестами** — упавший тест: запустить → autopsy → фикс → перезапуск →
   зелёный + runtime-diff. Приоритетный сценарий продукта. **(M, зависит от 1)**
6. **Android-набор**: logcat, парсинг ANR/crash, состояние устройств (`adb devices`), скриншот
   экрана устройства в контекст (vision-модели). **(M)**

## Столп 2 — Память и контекст (ум)

Фундамент положен в 0.0.68 (stable prefix, decisive compaction). Дальше — знание, которое копится.

1. **Автообучение базы знаний** — извлекать NAV/STYLE/LESSON из каждой сессии автоматически
   (сейчас kb_record ручной и почти не используется); фоновая консолидация: дедуп, устаревание,
   проверка NAV-якорей через PSI. **(M)**
2. **Карта репозитория** — компактная «tree + сигнатуры» (à la Aider repo-map) из индекса IDE как
   дешёвая ориентация первой итерации вместо текстового project_overview. Кэш с инвалидацией по
   VFS-событиям. **(S)**
3. **Векторный ранкер бандла** — доделать `graceVectorRanker` (флаг уже есть): локальные эмбеддинги
   (ONNX MiniLM) без внешних вызовов; фолбэк — детерминированный ранкер. **(M)**
4. **Межсессионная память** — «мы это уже чинили»: поиск по сводкам прошлых сессий (они уже
   персистятся), топ-3 релевантных в бандл новой задачи. **(S)**

## Столп 3 — Надёжность и доверие (trust)

Агент, которому не доверяют правки, не используют. Доверие = обратимость + верификация.

1. **Откат хода агента одним кликом** — снапшот через IntelliJ Local History в начале тёрна,
   кнопка «Revert this turn» в чате. Психологически разблокирует авто-approve. **(S, огромный эффект)**
2. **Верифицируемые правки** — после каждого edit_file автоматически `diagnostics`; новые ошибки →
   агент чинит или откатывает сам, прежде чем идти дальше. **(S)**
3. **Диф-карточки в чате** — правки показываются как diff с Apply/Undo по файлу (сейчас применяются
   молча; юзер узнаёт из тул-строки). **(M)**
4. **Финальное само-ревью** — для многофайловых задач: последний проход author-tier по общему диффу
   тёрна («что я сломал?») перед отчётом. **(S)**
5. **Регрессионный тест к каждому фиксу** — после root cause агент предлагает/пишет тест,
   воспроизводящий баг, и включает его в верификацию. **(M)**

## Столп 4 — Скорость и стоимость (двигатель)

1. **Адаптивный роутинг** — тиринг (навигатор/автор) сделать умным: классификация сложности шага →
   выбор модели автоматически, без ручного флага. **(M)**
2. **Исполнение тулов по мере стриминга** — стартовать read-only тулы, как только их JSON достримился,
   не дожидаясь конца ответа (fine-grained tool streaming). Минус секунды с каждой итерации. **(M)**
3. **Полировка локальных моделей** — Ollama/vLLM function-calling квирки, авто-подстройка
   maxContextTokens по `/models` метаданным провайдера, где доступно. **(S)**
4. **Бюджет-адаптивная компакция** — цель уже есть (70%); добавить профиль «дешёвый режим»: агрессивнее
   сжатие + haiku-класс на навигации. Одна галка «экономить». **(S)**

## Столп 5 — Кокпит (UX)

1. **Живой план** — панель «что агент делает»: текущий план/шаг/файлы (из notes + activeTask),
   а не только лог тулов. **(M)**
2. **Интеграция в редактор** — gutter-иконки трейспоинтов/брейкпоинтов агента; action «Ask geai»
   по выделению; intention «объясни/почини» на ошибке. **(M)**
3. **Экспорт сессии** — markdown-отчёт расследования (для тикета/PR-описания). **(S)**
4. **Коммит-ассист** — сгруппировать изменения тёрна, предложить commit message. **(S)**

## Столп 6 — Экосистема (охват)

1. **Hub/Spoke мульти-IDE** *(уже в работе — geai-hub)* — оркестрация нескольких geai:
   фуллстек-баг чинится связкой backend-IDE + Android-IDE, контракты через OpenAPI-паблиш.
   Ни у одного конкурента нет мульти-IDE рантайм-кооперации. **(L, дифференциатор №2)**
2. **MCP-клиент** — geai потребляет внешние MCP-серверы: Sentry (issue → рантайм-дебаг по стеку!),
   Jira/YouTrack, БД. Sentry-сценарий — прямое усиление моата. **(M)**
3. **Публикация** — JetBrains Marketplace, доки-сайт, 3 демо-видео (обязательно: runtime-diff и
   трейспоинты — то, что текстовые агенты не повторят). **(M)**

## Столп 7 — Измеримость (доказательство «лучшести»)

«Лучший в мире» — утверждение, требующее чисел.

1. **Бенчмарк-харнесс** — развить `benchmark/`: 20–30 воспроизводимых задач, из них ≥10 «рантайм-багов»
   (решаемых только через дебаггер/трейсинг — собственный класс задач, где конкуренты — 0%).
   Метрики: resolve rate, медиана итераций, cost/task, wall-time. **(M, начать рано)**
4. **CI-гейт** — прогон smoke-набора на каждый релиз; регрессия метрик блокирует релиз. **(S)**
3. **Opt-in телеметрия** — анонимные счётчики: компакции, абортов stuck-guard, cache-hit rate,
   итераций/задачу. Это данные для тюнинга промптов и гардов. **(S)**

## Фазы

### Фаза 1 — «Глаза и доверие» (0.0.7x, ~2-3 недели)
Максимум эффекта на строку кода:
- read_run_output + logcat (1.1) · failure autopsy (1.2)
- Revert-this-turn через Local History (3.1) · diagnostics после правок (3.2)
- Карта репозитория (2.2) · межсессионная память (2.4)
- Бенчмарк v1: 10 задач, включая 5 рантайм-багов (7.1)
- **Гейт фазы:** resolve rate на своём наборе ≥ 60%, ноль абортов stuck-guard на наборе.

### Фаза 2 — «Доказательства» (0.0.8x, ~месяц)
- Runtime-diff (1.3) · watchpoints (1.4) · замкнутый цикл с тестами (1.5)
- Диф-карточки (3.3) · само-ревью (3.4) · регрессионный тест к фиксу (3.5)
- Векторный ранкер (2.3) · автообучение KB (2.1) · адаптивный роутинг (4.1)
- **Гейт:** рантайм-задачи ≥ 80%, cost/task −30% к Фазе 1.

### Фаза 3 — «Сеть» (0.0.9x, ~месяц-полтора)
- Hub-сценарии фуллстек (6.1) · MCP-клиент + Sentry (6.2) · Android-набор (1.6)
- Живой план (5.1) · интеграция в редактор (5.2) · streaming-исполнение тулов (4.2)
- **Гейт:** демо «Sentry issue → доказанный фикс с runtime-diff» проходит без ручных подсказок.

### Фаза 4 — «Выход» (1.0)
- Marketplace, доки, демо-видео, публичный бенчмарк-отчёт (сравнение с Claude Code/Cursor на
  рантайм-наборе), экспорт сессий, коммит-ассист.
- **Гейт:** установка «с нуля до первого доказанного фикса» ≤ 10 минут у стороннего человека.

## KPI (сквозные)

| Метрика | Сейчас (оценка) | 1.0 цель |
|---|---|---|
| Resolve rate, рантайм-набор | ~30–40% | ≥ 85% |
| Медиана итераций на баг-диагноз | 8–15 | ≤ 6 |
| Cache-hit rate (после 0.0.68) | 80–95% | ≥ 90% удерживать |
| Cost/задача (Sonnet-класс) | ~$0.5–2 | ≤ $0.5 |
| Аборты stuck-guard / 100 задач | ? (мерить) | < 2 |
| Time-to-first-token итерации | 1–3 c | ≤ 1.5 c |

## Анти-цели (чего сознательно НЕ делаем)

- **Не** возвращаем зоопарк гардов и мандатов в промпт — проблемы решаются структурно (урок 0.0.68).
- **Не** строим свой CLI/веб-версию — сила geai в IDE, распыление убьёт моат.
- **Не** гонимся за чат-фичами общего назначения (персоны, темы, войс) — это не двигает KPI.
- **Не** добавляем провайдеро-специфичные хаки, ломающие остальных (урок: всё должно работать
  на OpenRouter/DeepSeek/локальных так же, как на Claude).
- **Не** копим фичи без бенчмарка: фича без движения метрики — кандидат на удаление.

## Риски

| Риск | Митигция |
|---|---|
| Churn платформенного API (каждый major IDE) | слой DebuggerSupport/PSI уже изолирует; CI на EAP |
| Лимиты/цены провайдеров | провайдер-независимость — уже ядро; локальные модели как фолбэк |
| JCEF-квирки (AS, Linux) | Swing-фолбэк поддерживать функциональным (0.0.70 — баннер+диагноз) |
| Хаб уводит фокус с ядра | хаб — Фаза 3, только после гейтов Фаз 1–2 |
| Бенчмарк переобучение («учим набор») | половина набора — скрытая, ротация задач |
